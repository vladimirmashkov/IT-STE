# Представления для LLM

[English](README.md)

Этот каталог описывает формат, а не готовый экспортёр. Канонические данные находятся в `standards/`; JSONL, Markdown-пакеты и индексы должны генерироваться из них. Обучающие пары, синтетические примеры и ответы моделей не считаются нормативным текстом.

## Работа с языками

Английский (`en`) — основной язык и язык выгрузок по умолчанию. Русский (`ru`) — предпочтительный второй язык. Русский и остальные переводы опциональны и могут быть частичными.

Выгружайте один язык за раз, если явно не запрошен и не описан в манифесте смешанный пакет. Приложение не должно незаметно использовать другой язык при отсутствии запрошенного перевода. Оно может применить явно заданную политику переключения или сообщить, что запрошенная запись недоступна. См. [языковую политику](../docs/language-policy.ru.md).

## Выбор корпуса

Выгрузка требует явных `standard`, `version`, `revision`, `language` и полного commit ID репозитория. Не используйте неявный `latest` и не смешивайте ASD-STE100 с IT-STE, разные версии или языки в одном пакете без отдельного явно описанного состава.

По умолчанию включаются только:

- записи из манифеста снимка со статусом `released`, зарегистрированного в `catalog.json`;
- записи со статусом `approved`, без маркера `template`;
- записи с проверенными правами на распространение и выполненными условиями лицензии;
- переводы с разрешимой ссылкой `translation_of` и совпадающим `source_sha256`.

Библиографические метаданные ограниченного источника не являются разрешением выгрузить его текст. Черновики, отозванные записи, шаблоны и локальные PDF не индексируются как нормативные правила.

## Разрешённый производный справочник

Для Issue 9 опубликован разрешённый машиночитаемый производный файл в версионируемом и отслеживаемом Git каталоге `reference/`. Это сохраняемый артефакт публикации, а не временный результат сборки. Исходный PDF остаётся закрытым и не входит в репозиторий. См. [инструкцию по производному справочнику ASD-STE100](../docs/asd-ste100-local-reference.ru.md) и [запись о разрешении](../docs/permissions/asd-ste100-issue-9-derivatives.ru.md).

Вместо загрузки всего стандарта в контекст LLM индекс возвращает короткие результаты и выдаёт полный фрагмент только по явному `--full`. Он сохраняет хеш источника, редакцию, физические страницы PDF, резервный вывод страницы, предупреждения извлечения, состояние прав и границу между производным содержимым ASD и собственными метаданными проекта. Пересобирайте его только через аутентифицированный процесс `build` и `publish`.

## Каталог выгрузки

```text
exports/<standard>/<version>/<revision>/<language>/<commit>/
  manifest.json
  rules.jsonl
  terms.jsonl
```

`exports/` исключён из Git. Публикация готового пакета возможна отдельно при соблюдении лицензий. Векторные индексы и эмбеддинги — отдельный кэш в `.cache/`, привязанный к этому снимку и конкретной модели эмбеддингов.

Манифест выгрузки фиксирует `schema_version`, точные координаты снимка и язык, полноту языкового покрытия, commit ID, путь и SHA-256 канонического манифеста, версию экспортёра, число записей, хеши выходных файлов и сведения об атрибуции. Время сборки не включается в хешируемое содержимое, если требуется побайтовая воспроизводимость.

## Единица JSONL

Одна строка — один самостоятельный объект правила или смысла термина. Поля экспортируемого объекта:

| Поле | Назначение |
| --- | --- |
| `schema_version` | Версия формата выгрузки |
| `record_key` | `standard@version#revision/language/kind/id` |
| `standard`, `version`, `revision` | Точный стандарт и снимок, фильтры поиска |
| `language`, `kind`, `id` | Язык, тип и стабильный ID |
| `text` | Детерминированное текстовое представление полной записи для LLM |
| `record` | Полная каноническая JSON-запись без потери полей |
| `source_path`, `source_sha256` | Путь от корня репозитория и SHA-256 байтов канонической записи |
| `source_url` | Постоянная ссылка на файл в конкретном коммите, не на ветку `main` |
| `source_refs`, `translation_of` | Происхождение и точная связь перевода; копируются из записи |
| `rights` | Условия самой записи; копируются без замены лицензией проекта |
| `project_attribution` | Обозначение авторства, URL проекта и лицензия наших материалов/метаданных из `catalog.json` |

Повторение части полей в оболочке выгрузки намеренное: это производные метаданные для фильтрации, а не второй редактируемый источник. Они обязаны совпадать с `record` и каноническим манифестом.

`text` включает правило вместе с ограничениями и явно различёнными допустимыми/недопустимыми примерами. Для термина сохраняются смысл, часть речи, статус допустимости, альтернативы и примеры. Нельзя превращать отрицательный пример в рекомендацию, отрывая его от метки.

Записи сортируются по `(kind, id)`, JSON сериализуется детерминированно в UTF-8 с LF. Экспорт должен завершаться ошибкой при дублирующемся ключе, неразрешимой ссылке, несовпадающем хеше, неподтверждённых правах или невыполненном условии лицензии, а не молча терять происхождение. Автоматизация этих проверок пока не реализована.

## Использование в RAG

1. До поиска явно выбрать стандарт, версию, ревизию и язык. При сравнении стандартов сохранять метки происхождения у каждого результата.
2. Передавать в контекст полный смысловой блок с примерами и метаданными, а не только найденное предложение.
3. Показывать пользователю ID, версию, постоянную ссылку на запись и предусмотренную лицензией атрибуцию. Каноническая ссылка на проект: **https://github.com/vladimirmashkov/IT-STE**.
4. При отсутствии запрошенной версии или языка сообщать об этом, а не незаметно подменять их другими.

Сохранение лицензий и ссылок в JSONL облегчает корректное повторное использование, но само по себе не гарантирует, что LLM будет их воспроизводить: это обязанность приложения, использующего корпус. Условия стороннего материала сохраняются отдельно от лицензии нашей разметки.
