# Языковая политика

[English](language-policy.md)

## 1. Основной язык

Английский (`en`) — основной и нормативный язык IT-STE.

- Нормативные правила и термины IT-STE сначала создаются и утверждаются на английском.
- Каждая нормативная сущность опубликованного снимка IT-STE должна иметь утверждённую исходную запись на английском.
- Документация репозитория без языкового суффикса, например `README.md`, написана на английском и является канонической.
- Машиночитаемые имена полей, идентификаторы, схемы и метаданные участия пишутся по-английски.
- При расхождении перевода с английским исходным текстом IT-STE действует английский текст.

Английский оригинал ASD-STE100 также имеет приоритет над любым переводом, который хранит проект. Эта политика не изменяет права на материалы ASD-STE100.

## 2. Дополнительные языки

Русский (`ru`) — предпочтительный второй язык. Это первый язык перевода, но русский перевод не обязателен для выпуска английской версии IT-STE. Он может быть полным или частичным и может появиться в следующей ревизии корпуса.

Все остальные языки опциональны. Для них используются корректные теги BCP 47, например `de`, `fr` или `pt-BR`. Даже полный перевод не становится вторым нормативным оригиналом.

В имени перевода документа языковой тег ставится перед расширением:

```text
README.md       # канонический английский документ
README.ru.md    # опциональный русский перевод
guide.md        # канонический английский документ
guide.ru.md     # опциональный русский перевод
```

Каждый перевод документа должен ссылаться на английский оригинал. Отсутствующий или устаревший перевод не должен задерживать исправление английского текста.

## 3. Записи стандарта

Язык — явная координата каждой записи правила или термина:

```text
content/en/rules/ITSTE-R-0001.json
content/ru/rules/ITSTE-R-0001.json
```

Перевод:

- использует тот же ID сущности и `kind`, что и английский оригинал;
- содержит собственное значение языка BCP 47;
- использует `origin: translation`;
- закрепляет `translation_of` за точными стандартом, версией, ревизией, языком, типом и ID источника;
- хранит SHA-256 канонического файла источника;
- сохраняет нормативный смысл, ограничения, примеры, происхождение и права источника.

Адаптация не является переводом. Она получает собственный ID IT-STE и явную связь `adapted_from`.

## 4. Манифесты и полнота

Значение `primary_language` — `en`. Массив `languages` перечисляет только языки, записи которых присутствуют в снимке. Объект `language_coverage` использует те же языковые теги и значения полноты `partial` или `complete`.

Для опубликованного снимка IT-STE:

- `en` должен присутствовать в `languages`;
- `language_coverage.en` должен быть равен `complete`;
- русский и другие переводы могут отсутствовать либо иметь полноту `partial` или `complete`;
- перевод не может существовать без разрешимой закреплённой ссылки на исходную запись.

Полнота измеряется относительно нормативных сущностей того же снимка, а не только количеством файлов. Перевод, в котором намеренно пропущено нормативное поле, не является полным.

## 5. Использование с LLM

LLM-выгрузки разделяются по языкам. Если приложение не указало язык, по умолчанию используется английский. Приложение может явно запросить русский или другой доступный язык, но не должно незаметно подменять язык или версию.

Каждая экспортированная запись сохраняет язык, ссылку на источник и перевод, права и атрибуцию проекта. Для смешанного многоязычного корпуса требуется явный манифест выгрузки и языковая метка в каждой записи.
