# Процесс адаптации IT-STE

[English](it-ste-adaptation.md)

Основным является английский документ. План адаптации преобразует закреплённую ревизию источника ASD-STE100 в проверенные редакторские решения до создания нормативных записей IT-STE.

## Текущий план

Первый план закреплён за ASD-STE100 Issue 9, ревизия представления `r0001`:

```text
standards/it-ste/
  domains/v1.0.0.json
  adaptation-plans/asd-ste100/issue-9/r0001/
    manifest.json
    map.jsonl
    targets.json
```

`domains/v1.0.0.json` определяет стабильные черновые идентификаторы IT-контекстов. В `map.jsonl` есть одна запись для каждого из 53 правил и 8 общих рекомендаций источника. `targets.json` описывает каждую планируемую концепцию правила IT-STE и породившие её решения по источнику, но не становится нормативным текстом. Манифест плана аутентифицирует исходную базу, реестр доменов, карту и реестр целей по SHA-256.

План не является релизом IT-STE, предварительные домены не нормативны, а целевой ID правила не назначается до редакторского решения о необходимости правила. Первичные кандидаты определяются по заголовкам; рассмотренные классификации также используют ограниченные фрагменты источника и редакторскую оценку применимости к IT.

## Состояния оценки

Каждый исходный блок проходит независимые состояния:

- `assessment.status`: `unreviewed`, `in-review` или `reviewed`;
- `assessment.applicability`: смысловое решение `pending`, `adopt`, `adapt` или `not-applicable`;
- `assessment.adaptation_action`: `pending`, `create-rule`, `create-rules`, `merge-into-rule` или `record-rationale-only`.

Для `reviewed` обязательно непустое английское поле `rationale` и одно согласованное решение:

| Применимость | Действие | Целевые ID |
| --- | --- | --- |
| `adopt` или `adapt` | `create-rule` | ровно один |
| `adopt` или `adapt` | `create-rules` | два или больше |
| `adopt` или `adapt` | `merge-into-rule` | ровно один; его могут совместно использовать только другие действия merge |
| `not-applicable` | `record-rationale-only` | отсутствуют |

`applicability` фиксирует сохранение или изменение смысла источника, а `adaptation_action` — структуру one-to-one, one-to-many или many-to-one. Только проверенные оценки могут назначать целевые ID.

Предварительные домены используют ID из закреплённого реестра `standards/it-ste/domains/v1.0.0.json`. Целевые ID имеют точный вид `ITSTE-R-NNNN` и обозначают собственные правила IT-STE, а не правила ASD.

## Проверка одного исходного блока

1. Аутентифицируйте источник и план:

   ```sh
   python3 tools/asd_ste100_local.py doctor
   python3 tools/it_ste_adaptation.py check
   ```

2. Прочитайте компактную карточку источника. Для конкретного вопроса используйте ограниченный фрагмент, а `--full` — только если контекста всё ещё недостаточно:

   ```sh
   python3 tools/asd_ste100_local.py rule 5.2
   python3 tools/asd_ste100_local.py excerpt 5.2 "one instruction"
   python3 tools/asd_ste100_local.py rule 5.2 --full
   ```

3. Изменяйте только запись этого блока в карте. Объясните, что применимо к IT, что требуется изменить и почему. По умолчанию не копируйте формулировку источника в правило IT-STE.
4. Назначайте целевые ID только после решения создать, разделить или объединить правила. Добавьте или обновите соответствующую ненормативную концепцию в `targets.json`; набор её исходных ID должен точно совпадать с картой.
5. Обновите хеши и количества, затем проверьте план:

   ```sh
   python3 tools/it_ste_adaptation.py seal
   python3 tools/it_ste_adaptation.py check
   ```

Команда `init` создаёт план, только когда ни одного файла плана ещё нет, и никогда не перезаписывает ручную работу. После изменений карты используйте `seal`. Если изменились байты закреплённого реестра доменов, `seal` остановится до проверки классификации; только после неё используйте `seal --accept-domain-change`, чтобы явно зафиксировать миграцию.

## Сквозной обзор целей

Для всех 61 исходного блока приняты рассмотренные решения и назначен 31 планируемый целевой ID. [Сквозной обзор](it-ste-plan-review.ru.md) фиксирует хэши проверенного состояния, три уточнения и границы целей. Все ID и исходные сопоставления сохранены. Отчёт является редакторским свидетельством, а не одобрением релиза или смысловой гарантией команды `check`.

До канонической материализации нужно определить контракт исходных и смысловых координат, границы прозы и литералов, а также приоритет профилей. Рекомендации сохраняют `kind: guidance`; текстовые ссылки не создают автоматически дополнительные связи происхождения. Проверьте контракт на небольшом пилоте до массового написания.

## От плана к стандарту

Рассмотренные решения карты служат входными данными, но не заменяют канонические записи IT-STE. Запись `targets.json` остаётся ненормативной плановой концепцией и не превращается в каноническую запись. Английское правило с тем же стабильным ID создаётся в версионируемом снимке `standards/it-ste/versions/<version>/revisions/<revision>/content/en/`; материализацию фиксируют манифест снимка и связи адаптации. Сохраняйте точные координаты источника и обоснование, считайте русский перевод опциональным и подчинённым английскому, а представления для людей и LLM создавайте из канонических записей.

[Канонический draft-контракт](it-ste-canonical-pilot.ru.md) теперь охватывает все 31 английское draft-правило с исходными и смысловыми координатами, точными привязками к плану, структурными примерами и критериями ручной проверки. [Единый черновик](IT-STE-draft.md) генерируется из этих записей; [последовательный разбор словаря](it-ste-vocabulary.ru.md) остаётся отдельным от утверждённых словарных записей. Команда `python3 tools/it_ste_corpus.py check` проверяет только этот закрытый профиль. Она не утверждает прозу, не завершает словарь и не выпускает снимок; план не меняется, публичный каталог остаётся пустым.

Текущий профиль инструмента намеренно закреплён за Issue 9 `r0001`. Для будущей редакции источника или исправленного представления создаётся отдельный неизменяемый путь плана и доверенный профиль источника; этот план нельзя перепривязывать к другому источнику.

Проект является независимой работой, а не официальной рекомендацией ASD. Сохраняйте сведения о правах ASD для производного содержимого и обязательную ссылку IT-STE: https://github.com/vladimirmashkov/IT-STE.
