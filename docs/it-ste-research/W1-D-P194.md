External evidence (inspected 2026-10-22):
- [Kubernetes Job v1 API reference](https://kubernetes.io/docs/reference/kubernetes-api/workload-resources/job-v1/); Kubernetes Authors, official generated API reference, v1.37 page, last modified 26 August 2026, `JobStatus.startTime` and `JobSpec.activeDeadlineSeconds`. The API defines `startTime` as the time when the Job controller started processing a Job, represents it in RFC3339 UTC, and uses it as the reference for an active deadline. This is direct primary evidence for a named operation's recorded start time. It is Kubernetes-specific and does not establish a universal lexical rule.
- [OpenTelemetry Tracing API](https://opentelemetry.io/docs/specs/otel/trace/api/); OpenTelemetry Authors, official specification, status Stable, sections `Span`, `Span Creation`, and `Span lifetime`. The specification defines a Span as one operation with start and end timestamps; says the timestamps reflect the operation's elapsed real time; and defines the start time as recorded when the Span is created unless an explicit logical start timestamp is supplied. This is primary observability evidence for an operation start event/timestamp. It does not prescribe the ASD vocabulary or make `commencement` a preferred term.

Alternatives and decision: Resolve both source/layout blockers while preserving draft status and source warnings. For `commence`, change to `prohibited`: the authenticated row maps to `START`, and the existing draft `START (v)` sense provides the shorter, observable operational action. Keep `start` as the contextual alternative; do not use a formal synonym when the operation and prerequisite can be stated directly. For `commencement`, change to `restricted`: retain only the bounded `logs-events` sense of a recorded start event or start time for a named operation, with the operation and time basis identified. Use `operation start time` or `job start event` in new wording. Reject `allowed` because neither external source supports unrestricted use of this spelling and both support more precise `start` fields/timestamps. Reject `prohibited` for the noun because the bounded event/time sense is technically real, as shown by Kubernetes `startTime` and OpenTelemetry start timestamps. The disposition choices and IT wording are editorial inferences, not ASD guidance or vocabulary approval.
