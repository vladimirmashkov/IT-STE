External evidence (inspected 2026-10-22):
- [because](https://dictionary.cambridge.org/dictionary/english/because) and [because of](https://dictionary.cambridge.org/dictionary/english/because-of); Cambridge Dictionary / Cambridge University Press, Cambridge Advanced Learner's Dictionary and English Grammar Today. The inspected grammar explains that `because` introduces a subordinate clause of cause or reason, while `because of` is a two-word preposition meaning “as a result of”; it also notes that `as` and `since` can shift focus or introduce ambiguity. This is competent linguistic evidence for form and meaning, not an IT error-message standard.
- [AIP-193: Errors](https://google.aip.dev/193); Google API Improvement Proposals, Approved, updated 2024-10-18. It says error messages should help a reasonably technical user understand and resolve the issue, remain brief and actionable, use simple descriptive language, and expose a machine-readable reason where applicable. This is directly relevant expert guidance for Google APIs, not a universal requirement for every IT message.
- [RFC 9457, Problem Details for HTTP APIs, §§1, 3.1.4, 4, 5](https://www.rfc-editor.org/rfc/rfc9457.html); Nottingham, Wilde, and Dalal, IETF, Internet Standards Track, July 2023. It defines occurrence-specific human-readable detail that should focus on helping the client correct the problem, and warns that problem information must be vetted for implementation and security disclosure. This is controlling evidence for the narrow HTTP problem-details model, not grammar or proof of causation.

Alternatives and decision: Change both records to `restricted`. Define `because` as introducing a clause that identifies the cause of a stated condition, and `because of` as introducing a noun phrase that identifies that cause. Retain them because concrete, evidence-supported causal explanations are useful in error messages and are consistent with the ASD meaning and API guidance. Reject `allowed` because an unrestricted sense can present a coincident event or vague symptom as the cause; reject `prohibited` because the inspected API guidance uses concrete causal explanations as part of useful error communication. Replace `confirmed cause` with `identified cause`: the external sources support specific, actionable explanations but do not establish an absolute confirmation threshold, while the problematic examples preserve the required distinction between evidence and correlation. Keep `as` and `since` only as contextual alternatives for `because`, with the note that they can change focus or be ambiguous; retain `as a result of` and `caused by` as contextual alternatives for `because of`. The disposition, definitions, examples, and certainty boundary are draft editorial inferences, not ASD provenance or external approval.
