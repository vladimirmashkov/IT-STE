State: resolved-draft
Question and scope: Does `corresponding` (adj) support a bounded API sense for an item related to a named request, response, resource, or operation through an explicit link or mapping? Scope excludes equality, generic similarity, temporal synchronization, and an unspecified association; it does not establish a general API vocabulary approval.

External evidence:
- [OpenAPI Specification v3.1.0 — Link Object](https://spec.openapis.org/oas/v3.1.0.html#link-object), OpenAPI Initiative, version 3.1.0 dated 2021-02-15, accessed 2026-10-22, section 4.8.20. The specification defines a Link Object as a known relationship and traversal mechanism between a response and another operation; it requires a target operation identified by `operationRef` or `operationId` and supports mapping runtime request/response values into target parameters. This is primary API specification evidence for explicit correspondence, but it does not make linked objects equal or guarantee a successful call.
- [RFC 8288 — Web Linking](https://www.rfc-editor.org/rfc/rfc8288.html), M. Nottingham, IETF, Standards Track, October 2017, accessed 2026-10-22, sections 2, 2.1, and 3.2. RFC 8288 defines a link as a typed connection between a link context and link target and states that a relation type describes how the context is related to the target. This is primary general web-link evidence; it does not prescribe the semantics of a particular API field or relation name.
Alternatives and decision: Change `D-P204-005` from `needs-review` to `allowed` while retaining `draft` / `editorial-review-needed`. Use “Related to a specified API item through an explicit link or mapping, provisionally.” The row boundary, spelling, POS, and source meaning are source facts. Keep the existing contextual alternatives and examples, but require the reference item or mapping to be identifiable. Reject “same as” or “equal to” because the sources describe relationships and traversal, not identity; reject bare “associated with” because it does not require an explicit reference; reject unrestricted “matching” because correspondence can be defined by a relationship or mapping rather than value equality.
Remaining uncertainty / escalation: OpenAPI and RFC 8288 support explicit relationships but do not determine every product’s use of `corresponding`, nor whether IT-STE should allow the term outside API documentation.
